# Stale — Build Plan

> **Project paused 2026-04-27 — hackathon ended.** Current state captured in
> [`STATE.md`](../STATE.md) at repo root. The plan below is preserved as the
> original roadmap; "Status" sections at the end of each phase note what was
> actually shipped vs. what's left.

Sequenced phases, each with a concrete deliverable. Hours are estimates.

## Phase 1 — Foundation

- Repo skeleton: `pyproject.toml`, `.env.example`, `.gitignore`, `stale/` package layout
- Install deps: `anthropic`, `pymupdf`, `python-pptx`, `jinja2`
- `stale/tools/extract.py` — PDF + PPTX extraction, PPTX speaker notes included
- `stale/setup_agents.py` — one-time `agents.create()` for the 3 agents, prints + persists agent IDs to `.env`

**Deliverable:** `python -m stale.setup_agents` outputs 3 agent IDs.
`python -m stale.tools.extract <file>` produces clean text.

**Status: ✅ DONE.** Three agents + 1 environment created and persisted to `.env`. Extraction working on PDF + PPTX (with notes). One bug found and fixed mid-Phase-2: `slide.has_notes_slide` can return True with a None `notes_text_frame`; guarded.

## Phase 2 — Auditor agent

- `stale/prompts/auditor.md` — system prompt
- `stale/agents/auditor.py` — session driver: opens stream, sends initial message with extracted curriculum, parses structured JSON output
- Test on 6 courses solo; iterate prompt until findings are sharp + cited

**Deliverable:** `python -m stale.agents.auditor` produces a JSON file of audit findings with primary-source citations.

**Status: ✅ DONE + extended.**
- Auditor prompt + driver shipped.
- `--limit N` and `--course NAME` flags added for targeted runs.
- **Added (not in original plan):** `stale/verify.py` — deterministic Python pass that re-fetches every `citation_url` and substring-checks the `citation_excerpt`. Catches LLM-fabricated URLs/quotes for ~zero cost. Calibrated against negative + positive test fixtures.
- **Added:** `stale/web/` — full FastAPI UI (upload form, run pages, Findings / Market-fit / Topics tabs, verified citation cards).
- **Smoke run:** Computer & Data Security course → 10 findings, 10/10 verified against NIST/Oracle primary sources. ~$0.30, 6.8 min.
- **Not done:** scaling to all 8 courses in one run (each course is independently verified, but no batch run was done).

## Phase 3 — Market-fit + Topics

- `data/job_postings.json` — ~100 role-tagged postings
- `data/skill_to_tool.json` — skill → industry-current-tool mappings
- `stale/prompts/market_fit.md`, `stale/agents/market_fit.py` — extract skillset, compare to postings, output gaps
- `stale/prompts/topics.md`, `stale/agents/topics.py` — consume market-fit output, rank missing topics

**Deliverable:** Market-fit produces gap analysis JSON; Topics produces ranked prescription JSON.

**Status: ✅ DONE for the agents and dataset; integration into the UI not done.**
- `data/job_postings.json` — 108 postings, 12 per role × 9 roles, generated by [`data/build_postings.py`](../data/build_postings.py) with frequency rates calibrated to public 2025 industry surveys (Stack Overflow, Octoverse, LinkedIn). See [`data/README.md`](../data/README.md). Decision recorded in `decisions.md` (#9).
- `stale/agents/market_fit.py` shipped; takes `--role` + curriculum, mounts both, produces `market_fit.json`.
- `stale/agents/topics.py` shipped; takes Market-fit's JSON as input message + postings dataset mounted, produces `topics.json`.
- **`data/skill_to_tool.json` not built** — turned out to be unnecessary. The agents work directly off the postings + curriculum without needing a skill→tool mapping lookup table.
- **Smoke run:** Market-fit on Security course (`role=security`) → 24 gaps, headline "prepares the student for a ~2010 enterprise security-analyst role". Topics on that → 10 ranked prescriptions. ~$0.55 total, ~9 min combined.

## Phase 4 — Orchestrator + report

- `stale/orchestrator.py` — fan-out parallel for Auditor + Market-fit, sequential for Topics, aggregate outputs
- `stale/report/template.html` + `stale/report/render.py` — Jinja2 template, clean visual report

**Deliverable:** `python -m stale.orchestrator` produces `report.html` with everything stitched together.

**Status: 🚫 NOT STARTED.** Each agent driver works standalone. The orchestrator was the next thing on deck when the project paused. The web UI's run page can be extended to show market-fit + topics results — currently it only renders auditor findings.
